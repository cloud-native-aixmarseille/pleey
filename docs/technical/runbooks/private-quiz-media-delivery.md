# Replace public quiz media delivery with signed access

Use this procedure only when a deployment has already published quiz media through public object URLs. Fresh installations follow [media operations](../development/backend/operations.md#quiz-media-storage-processing-and-delivery). The access decision and bounded lifetime are recorded in [ADR 0012](../architecture/adr/0012-support-media-on-quiz-questions.md).

1. Stop traffic and all old backend replicas that disclose permanent URLs or shared party media links. Record the existing delivery origins and object prefixes so none remain publicly readable.
2. Remove anonymous read identities, public ACLs, and public bucket policies from the storage origin. Configure the delivery route to preserve signed Host/path/query and to validate every request at the private origin. Disable caching for objects and error responses, and remove any CDN origin credential policy that bypasses viewer signature validation.
3. Purge all previously cached quiz objects from every public CDN hostname and retire any alternate public delivery route. Change existing object cache metadata to `private, no-store` where supported; the backend also signs a response-cache-control override and the development proxy enforces this header. A previously downloaded or browser-cached public response cannot be recalled. If public browser caches remain within their old 24-hour lifetime, treat those bytes as already disclosed even after the infrastructure cutover.
4. Configure `MEDIA_ACCESS_TTL_SECONDS` and the exact signed delivery base URL, deploy the new backend/frontend together, and restart all media-origin/proxy services to apply private access settings. Do not resume the old backend against the private delivery route.
5. Verify an authorized editor, actual host, and joined guest receive expiring grants. Confirm unauthorized/unjoined/cross-party requests receive no media grant or question context. Test valid GET and Range requests and rejection of unsigned, expired, tampered, and HEAD-replayed GET URLs at both delivery and origin. Keep traffic closed until these checks pass.
6. Reopen traffic. Check grant refresh and playback after expiry, then confirm kick/leave/end prevents new player grants and permission loss prevents editor grants. An existing grant can remain valid until its configured expiry; this feature does not offer immediate revocation of downloaded bytes or individual grants.

Rotating the storage credential invalidates grants signed by that credential when the provider removes its validity. Restart backend replicas after rotation. Do not use credential rotation as routine participant revocation; it affects every active media viewer.
